协议实体与信任模型

PK 路径无 TTP；SK 路径的 TTP 交互发生在 AP 与 TTP 之间

STA 发起方 / 被认证方

non-AP Station
  • PK：持有自身私钥，并可信 AP 的公钥/证书链
  • SK：与 TTP 共享 rRK，或持有缓存的 PMKSA
  • 生成 SNonce、临时 DH 密钥、FILS Session
  • 推导 PMK/PTK，发送 KeyAuth，验证 AP 的 KeyAuth

AP 响应方 / Authenticator

FILS-capable AP
  • PK：持有自身私钥，并可信 STA 的公钥/证书链
  • SK：可选缓存 PMKSA；可连接 TTP
  • 生成 ANonce、临时 DH 密钥，校验对端公钥
  • 转发 EAP-RP，验证 KeyAuth，经 Key Delivery 下发 GTK

TTP / AS 仅 SK 路径

Trusted Third Party / Authentication Server
  • 与 STA 预先通过完整 EAP 建立 rRK
  • 验证 EAP-Initiate/Reauth
  • 返回 EAP-Finish/Reauth 与 rMSK
  • AP↔TTP 使用 RADIUS/Diameter，不在 802.11 范围内

路径 A：FILS Public Key Authentication（无 TTP）

算法号 6 · 始终使用 Diffie-Hellman（PFS）
A1STA → AP Authentication（Transaction Sequence = 1） 密钥建立 · 第 1 帧

发送前计算 STA

  • 从 dot11RSNAConfigDLCGroupTable 选群 G（须为 AP 所支持）
  • 生成临时私钥 skSTA 与公钥 gSTA = scalar-op(skSTA, G)
  • 生成 16 octet SNonce 与随机 FILS Session
  • 若尝试 PMKSA 缓存：RSNE 中填 PMKID List
  • gSTA 按 12.4.7.2.4 编码进 FFE

接收后处理 AP

  1. 群 G 不可接受 → 回 Status 77 并终止
  2. gSTA 八位串转群元素，按 NIST SP 800-56A 5.6.2.3.2 校验；失败终止
  3. 提取 SNonce、gSTA
  4. 检查 PMKID List：命中缓存 → 走缓存；否则 → 签名模式
  5. 生成 ANonce 与 (skAP, gAP)；计算 DHss = scalar-op(skAP, gSTA)
A2AP → STA Authentication（Transaction Sequence = 2） 密钥建立 · 第 2 帧

发送前计算 AP

  • 设置 Status = 0（成功）
  • 生成 16 octet ANonce
  • 在同一群 G 上生成 (skAP, gAP)
  • 回显 STA 的 FILS Session
  • 使用缓存时填入选中的 PMKID
  • 可延迟到发送前才计算 DHss

  5. 立即执行 PMK → PTK 推导，并删除 DHss

双方独立推导 · PMK / PMKID

PMK = HMAC-Hash(SNonce ‖ ANonce, DHss)
PMKID = Truncate-128(Hash(gSTA ‖ gAP))
PMK 长度 256 或 384 bit，由 AKM 决定；PMKID 固定 128 bit。

双方独立推导 · PTK

PTK = PRF-X(PMK, "FILS PTK Derivation", SPA ‖ AA ‖ SNonce ‖ ANonce)
SPA = STA MAC，AA = AP BSSID。非缓存 PK 的 PTK 不再附加 DHss。

拆分与使用

  • ICK → KeyAuth 的 HMAC（缓存场景）
  • PTK-KEK → AEAD 保护关联帧
  • TK → 后续单播数据帧
  • 生成完成后删除 DHss
A3STA → AP (Re)Association Request — 密钥确认 第 3 帧 · AEAD 保护

发送前计算 STA

  • 无缓存（首次 PK）：用 STA 私钥签名
    KeyAuth = Sig-STA(gSTA ‖ gAP ‖ SNonce ‖ ANonce ‖ STA-MAC ‖ AP-BSSID)
  • 使用缓存：改用 HMAC
    KeyAuth = HMAC-Hash(ICK, SNonce ‖ ANonce ‖ STA-MAC ‖ AP-BSSID ‖ gSTA ‖ gAP)
  • AAD = 四元地址 + Capability Information 起至 FILS Session（含）
  • FILS Session 之后的组件用 PTK-KEK 做 AEAD 加密
  • 把 STA 证书/公钥放入 FILS Public Key 元素，供 AP 验签

4

路径变体与失败分支

同一套四帧框架，不同字段与密钥输入

SK 无 PFS（算法 4）

  • 认证帧无 Finite Cyclic Group / FFE
  • PMK = HMAC(SNonce‖ANonce, rMSK)
  • KeyAuth 不含 gSTA/gAP
  • 依赖 rMSK 的保密性，无前向保密

SK with PFS（算法 5）

  • 两帧认证都带群 G 与 FFE
  • PMK = HMAC(SNonce‖ANonce, rMSK‖DHss)
  • KeyAuth 追加 gSTA‖gAP
  • 提供前向保密；群不支持 → 77

PMKSA 缓存（SK / PK）

  • Auth1 的 RSNE 带 PMKID List；Auth2 指示选中的 PMKID
  • 命中时不联系 TTP、不新建 PMKSA，沿用缓存 PMK/PMKID
  • 仍必须新建 PTKSA
  • 2024：缓存 + DH 时，PTK 推导追加 DHss
  • PK 缓存时 KeyAuth 由签名改为 HMAC(ICK)

失败与状态码

码含义
0成功
15TTP 挑战失败（EAP-RP 验证失败）
53无效 PMKID（未命中缓存且无 EAP-Initiate）
77有限循环群不支持
112FILS 认证失败（KeyAuth / AEAD 等）
113AP 不认识 STA 所指的认证服务器

密钥删除规则

  • PMK/PMKID 生成后：不可恢复地删除 rMSK 与 DHss
  • PTK 生成后：删除 DHss
  • AP 密钥确认失败：删 ICK/PTK-KEK/TK/PTKSA；未缓存则删 PMKSA
  • STA 密钥确认失败：删 ICK/PTK-KEK/PMK/TK，放弃交换
  • 认证成功：删除密钥建立阶段的非持久秘密材料

口径说明（以 IEEE 802.11-2024 §12.11 原文为准）

  1. 算法号：FILS SK 无 PFS = 4，SK with PFS = 5，PK = 6（§9.4.1.1）。前文中的“ANA-8”并非 FILS 分配值。
  2. 完整性密钥名称：FILS 使用 ICK（Integrity Check Key）计算 KeyAuth；部分资料写作 KCK。PTK 中对应字段为 ICK / PTK-KEK / TK。
  3. PMK 推导：标准公式为 HMAC-Hash(SNonce‖ANonce, …)（§12.11.2.5.2），不是 KDF-384 的 “FILS PMKSA Derivation” 形式；PMKID 公式见上表。
  4. PK 路径的证书位置：Auth 帧只携带 FFE = gSTA/gAP；设备证书/公钥在关联帧的 FILS Public Key 元素中传输。首次 PK 的 KeyAuth 是数字签名，只有命中 PMKSA 缓存时才用 HMAC(ICK)。
  5. TTP 与 AS：标准正文多称 Authentication Server（AS）；TTP 是同一信任实体的架构称谓。AP↔TTP 的传输（RADIUS/Diameter）不在 802.11 范围内。
快速性来源 ①认证帧本身承载密钥建立材料（DH 公钥或 Wrapped EAP-RP），两帧认证后即可产生 PMK。
快速性来源 ②密钥确认直接嵌入 (Re)Association Request/Response，不再单独运行 4 次 EAPOL 握手。
快速性来源 ③SK 的 TTP 交互发生在 AP↔TTP，不增加 STA 空中往返；PK 路径完全去除 TTP。

四帧完成后的状态

帧完成后的双方状态
① Auth (Seq=1)STA 发出 SNonce、gSTA（PK/PFS）、FILS Session；AP 完成群/公钥校验并生成 ANonce、gAP、DHss（如适用）
② Auth (Seq=2)双方得到对端 nonce 与 DH 公钥，独立推导 PMK / PMKID / PTK（ICK、PTK-KEK、TK），并删除 rMSK / DHss
③ (Re)Assoc RequestAP 用 PTK-KEK 解密并验证 KeyAuth，确认双方密钥一致；AP 侧安装 PTKSA，准备 Key Delivery
④ (Re)Assoc ResponseSTA 验证 AP 的 KeyAuth，安装 PTKSA 与 GTK（及 IGTK/BIGTK/WIGTK）；FILS 完成，可立即收发受保护数据
