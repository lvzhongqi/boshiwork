# RECORD —— 各协议的特殊情况

一个协议一节，记**这个协议独有的、会绊倒下一次运行的**事情：文档的怪写法、
ground truth 的特殊约定、反复出错的建模点。

**写法要求：**

- 尽量简洁，一条一两句话说清楚，不写背景铺垫。
- 每节抬头写更新时间。
- **更新时把过时的内容直接删掉**，不要留"原来是…现在改成…"的沿革。
- 通用的建模规律不写这里——那是 节点 docstring 或提示词该管的事。
- 没有特殊情况的协议不建节。

---

## EDHOC

更新时间：2026-08-23

- draft-08 的角色体是 `if 收到错误 then 0 else <整条协议>`，**成功路径在 else**。
  探针不能插在"进程体最后一个 `0`"，那是错误分支。
- `skV` 会同时落在 `data`（会话后泄露）和 `key_reuse`（第二用途）两根轴上，这是
  正常的，不是重复声明。

## TLS13

更新时间：2026-08-27

- ground truth（8446）把 `mode` 写成三个 `selected_*` 绑定，不是一个值；记录层的
  nonce 和附加数据装在一个没名字的元组里。claims 里的名字锚不上是预期内的，
  交给 inject 处理，不要为此改产物。
- 有多个 draft 变体（draft18/20/21/8446），ground truth 互不共享，别名要带完整路径。
  draft21 已裁决放弃。

## NSSK

更新时间：2026-08-27

- 会话密钥 `CK` 由 flow 模型内部 `new` 出来，principals.json 里没有。引用它的
  properties/claims 必须在 `extract_flow` 之后生成，否则会被判"名字不存在"。

## Neuman-Stubblebine

更新时间：2026-08-27

- verdict 不稳定：同一假设集两次跑可能回 unknown。做对比实验前先确认可复现性。
- 标准 query 带时序，我们的模型没有。

## Otway-Rees

更新时间：2026-08-27

- realizer 的 waives 是全场景豁免，在这个协议上把真问题一起消音过。看到 waive
  生效时多查一眼。
