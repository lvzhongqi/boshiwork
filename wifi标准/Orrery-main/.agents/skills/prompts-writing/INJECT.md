# Inject 安全目标提示词

适用于 `orrery/nodes/inject/` 下的节点提示词和各个 injector 的规则文件。

## 核心原则

把安全目标是什么、要观测哪段协议语义说清，让模型根据当前模型定位事件、值和插入位置。Inject 增加观测与 query，不改变协议消息、检查和分支，也不补造目标成立所需的安全假设。Authentication 的 end 和 Secrecy 的 witness 都根据完整模型判断本次运行认定的对端是否可能由攻击者控制，不区分它来自网络还是角色参数；需要守卫时，把 main 中已有的稳定诚实身份及凭证作为独立观察参数传入角色，并同步修改全部调用。守卫的参照按 main 对相应角色的实例化读取；角色实例由世界层保证只为诚实主体运行，注入器把每个实例当诚实运行读。

观测语义决定改动范围，不由示例里的代码形态决定。模型可以按需要增加声明，修改角色签名、
角色体中的观测位置、辅助观测结构、main process 和全部调用；相关定义与调用必须一起改完整。
这些授权用于准确表达目标，不改变协议消息、检查、分支和场景假设。

**注入器不感知假设。** 它拿到的是假设施加之后的模型文本，就把它当协议本身读。唯一需要判断的假设产物是 phase 边界，那也从模型文本里读，不从假设名字读。所以提示词里不出现任何轴名、取值名，也不出现场景名。

## 文件分工

`prompts/main.sys.md` 和 `main.user.md` 是节点级的，只做两件事：把模型放进系统块，把本批目标放进用户块。产出规程（id 命名、declarations 与 edits 的分工、锚点引用原文、`0.` 终止符）写在规则文件里，不写在节点提示词里。

规则文件叫 `rules.sys.md`，默认放在叶子目录（`injectors/<type>/<subtype>/`），由 `Injector.rules_dir()` 决定。Authentication 覆盖了它，一份规则放在大类目录下：四层机制相同，只差事件参数和 query 形式，而且它是唯一会把多个 subtype 放进同一次调用的类型。

以下规则在 `SKILL.md` 的通用标签规则上进行补充。

### 前缀语料块

`{{ pv }}` 代表已经应用完安全假设的场景模型。所有编辑锚点都逐字引用这份模型。

### `<task>`

说明你是形式化分析专家，要在上述 ProVerif 模型中注入指定安全目标，并提交声明和锚定编辑。

正向定义目标断言的安全语义、涉及的角色和值，以及一次成立或违反目标的执行应当是什么样子。一个大类下有多个层次时，用一张表把各层的断言、事件参数、query 形式并排写清楚。

最后说明提交什么：`declarations` 放位置无关的声明行，`edits` 放进程体内的语句以及必要的角色签名和 main 调用改写，并逐字引用锚点。

### `<constraints>`

对 query、event、witness 的注入位置进行限制，避免模型胡乱注入。诚实对端守卫比较本次运行认定的对端与独立的稳定诚实身份及凭证，守卫放在最后一次协议发送之后，作用域只含观测事件本身，协议语句不落入其中；begin 不守卫。一个可能传入攻击者身份或凭证的运行时值只能表示本次运行的身份，不能同时作为诚实参照；稳定值从 main 作为独立参数补入角色及全部调用。

还要有一条"让模型仍然是那个模型"：除观测构造以及上述观察参数传递外什么都不加，不加 `phase`、不加进程、不改消息形状。

### `<success_criteria>`

正确注入后的 pv 形态。

### `<example>`

例子完整展示一种目标机制中事件参数、witness、守卫、query 与相对插入位置的对应关系。使用其他协议的名字，不替当前模型决定本地变量和锚点。

## 用户提示词

`<input>` 放本批目标的 json（含 id、type、subtype、values、parties）；
最后用一句无标签祈使句提出本次任务；
`{{ step_messages }}` 收尾。
没有 `<context>`：本次调用除了模型和目标，没有别的背景。
