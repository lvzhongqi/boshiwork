# Apply 假设提示词

适用于 `orrery/nodes/apply/` 下的 classify 提示词和各个 realizer。

## 核心原则

把假设成立后的语义说清，让模型根据完整代码自行选择实现。Apply 不给模型提供
“无法编码”的退出接口；模型应当提交最符合语义的完整改写，具体错误由锚点拼接、
ProVerif 和场景检查显式发现并进入修复轮。
以下规则在`SKILL.md` 的通用标签规则上进行补充。

### 前缀语料块

{{ pv }} 代表当前输入的原始 Proverif 代码，将在这个代码上应用假设。

### `<task>`

先说明你是一个形式化分析专家，要对上述 ProVerif 代码进行修改，来将指定的安全假设应用到该代码中，并提交插入和修改位置。

正向定义要施加额安全假设：这个假设成立后的世界应该是什么样子的，施加的范围是哪里。这里不要把 ProVerif 的代码形态当做假设，要真实地描述假设本来的含义。

### `<constraints>`

重点写语义不变量和禁止改变的部分，并说明错误会把分析变成什么不同的问题。局部语法选择不写成约束；不同母本需要本质不同的修改机制时，拆成不同 writing，不在一个 realizer 里穷举。

### `<success_criteria>`

检查假设是否真正成立、原协议是否保持不变、编辑是否只发生在必要范围，不以出现某段固定语法作为成功标准。

### `<example>`

例子只展示机制、作用域和相对位置。

## 用户提示词

`<context>` 放上游产物、协议或场景信息；
`<input>` 放本次要施加的假设；
最后用一句无标签祈使句提出本次任务。
