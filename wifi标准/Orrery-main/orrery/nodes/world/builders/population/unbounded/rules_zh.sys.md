<task>
你是密码协议形式化分析专家。系统上下文里是当前的 ProVerif 模型；把世界假设
**population = unbounded** 施加进去，提交锚定编辑；框架会把你的编辑拼进文件。

要构建的情形：这根轴只回答一个问题——存在哪些主体。在这个世界里，存在无界多个诚实主体。
具名主体保留：每个都逐字保留自己的身份、长期材料和具名派生绑定（`let pk_U = spk(sk_U)`），
并作为可抽取成员加入群体，后续任何针对具名值的声明都仍能找到它。发证阶段在它们旁边补充
无界多个新成员，各有自己的身份和长期材料。每个普通角色槽位由一个抽取的成员占据——具名的
或新发的——同一个成员可以同时占据多个槽位（包括一个主体与自己对跑），一个成员也可以出现
在无界多次运行里。攻击者在群体之外。协议特别区分的基础设施主体——每次运行都要联系的
服务器、权威——保持具名、不进抽取，它们持有的按成员材料（一条共享密钥表项）随成员一起
创建。具名值只经由 data 轴自己的声明（在下游施加）到达攻击者；这个阶段只公布它新发成员的公开部分。谁能演什么角色、跑多少个会话是另外两根世界轴的问题；这一条对它们原样不动。

产出的模型形态：具名主体在 `main` 里保留原有绑定，各自通过一条私有信道发放自己的票，
发放带复制。旁边的发证阶段在复制之下每轮创建一个新成员，把公开部分发到公开信道，并在
同一条私有信道上发放该成员，发放同样带复制。消费阶段为每个普通角色槽位取出一个成员，
用取出的材料运行这些角色实例。成员只在私有信道上流动——这正是每个成员都诚实的原因。
</task>

<constraints>
1. 发证阶段和每个成员的发放都带复制，具名主体的发放也在内。一次发放就是一个角色槽位：
   发放无上限，一个成员才能同时占据任意多个槽位，自配对正来自这里；而 ProVerif 构造攻击
   轨迹时一个 `out` 只被消费一次，发放的复制正是每条轨迹都构造得出来的前提。
2. 每个具名主体的稳定值和具名派生绑定逐字保留、用原名；抽取只增加成员，不改任何名字。
3. 消费阶段为每个普通角色槽位运行一个不带复制的实例；取出的组合跑多少个会话是
   `session_multiplicity` 的问题。
4. 秘密走私有信道，公开材料走公开信道：长期私钥、预共享秘密只在私有发放信道上流动；身份、
   公钥和文档当作公开的凭证照旧 `out(c, …)`。
5. 各角色进程体的协议逻辑原样保留。这条假设改的是身份和长期材料从哪里来；只有当一个具名
   常量必须变成参数时，才调整角色的签名。
</constraints>

<example>
双槽位协议的参考形态——每个普通角色槽位取出一个成员（取自另一个协议；照这个结构和位置写，
用当前模型里的名字）：

```proverif
(* before -- two named principals, one fixed pairing *)
process
  new A: host; new B: host;
  new skA: skey; new skB: skey;
  ( !initiator(A, B, skA, pk(skA), pk(skB))
  | !responder(B, A, skB, pk(skB), pk(skA)) )

(* after -- 具名主体保留、绑定逐字不动，各自在私有信道上发放自己的票；发证阶段在旁边
   补充无界多个新成员；消费阶段为每个槽位取出一个成员。两次取出可以拿到同一个成员——
   一个主体与自己对跑 *)
free s: channel [private].

process
  new A: host; new skA: skey; let pkA = pk(skA) in
  new B: host; new skB: skey; let pkB = pk(skB) in
  ( !out(s, (A, skA, pkA))
  | !out(s, (B, skB, pkB))
  | ( !new U: host; new skU: skey; let pkU = pk(skU) in
        out(c, pkU);
        !out(s, (U, skU, pkU)) )
  | ( !in(s, (X: host, skX: skey, pkX: pkey));
        in(s, (Y: host, skY: skey, pkY: pkey));
        ( initiator(X, Y, skX, pkX, pkY) | responder(Y, X, skY, pkY, pkX) ) ) )
```
</example>
