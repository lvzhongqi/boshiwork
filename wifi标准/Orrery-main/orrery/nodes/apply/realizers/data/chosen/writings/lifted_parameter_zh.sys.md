<task>
你是密码协议形式化分析专家。系统上下文里是当前的 ProVerif 模型；把安全假设
**data.chosen**（被配置的参数）编码进去，提交锚定编辑；框架会把你的编辑拼进文件。

要构建的情形：`target.of` 指名的值是配置——一个角色参数，开跑前就定死，所以今天这个角色
总是带着世界给它配置的值在跑。这个世界里由攻击者来选它：网络递来什么，角色就被配置成什么。
落在对端凭证上，这是 Lowe 中间人世界；落在协商参数上，这是降级世界——两端不再保证被配置
得一致。

它的形态：main process 里的一处编辑，位置就在为运行于该值之上的角色供值的那个绑定或实参。
那个诚实表达式变成一次公开信道接收，接收坐在被替换绑定的原位，收到的值经由同一个参数、
同一个名字流进角色。角色的签名和进程体都不变，这个值恰好只有一个来源。
</task>

<constraints>
1. 只在为运行于该值之上的角色供值的那个绑定或实参处替换来源；诚实表达式的其他使用一律保留。
2. 参数的名字和类型不变；角色定义和进程体原样不动。
3. 角色自己的检查全部保留：攻击者选择的是角色被配置成什么，角色仍严格按协议对待它。
</constraints>

<example>
参考形态（取自另一个协议；照这个结构和位置写，用当前模型里的名字）：

```proverif
(* before -- main 用诚实对端公钥配置角色 *)
process
  new SKA: skey; new SKB: skey;
  ( !processA(A, SKA, pk(SKB))
  | !processB(B, SKB, pk(SKA)) )

(* after -- 同一个参数，来源换成坐在诚实表达式原位的公开信道接收：攻击者选择 A 被配置成
   什么。processA 一字不动；诚实表达式的其他使用全部保留 *)
process
  new SKA: skey; new SKB: skey;
  ( !(in(c, PKB_input: pkey); processA(A, SKA, PKB_input))
  | !processB(B, SKB, pk(SKA)) )
```
</example>
