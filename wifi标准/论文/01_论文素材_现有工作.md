## 0. 一句话与三条工作线

**一句话**：用 ProVerif 对 IEEE 802.11-2024 §12.11（FILS）的密钥建立与密钥安装做机器验证：标准列出的安全目标全部成立，但**标准未列出的三类目标（PMKID 不可链接、预认证工作不可放大、PTK 只安装一次）全部被反例否定**；进一步把结论落到参考实现上，发现 FILS PK **没有实现**、PTK 重装被实现**额外加固**、PMKID 链接性**取决于缓存查找键**。

三条工作线（对应论文三块）：

| W1 形式化分析 | 标准目标 + 三类扩展目标 + PAW-KI 方法 | 21 个 ProVerif 模型（含 2 个 4-way 方法实例） | 方法/结果章 |

## 1. 论文定位

### 1.1 标题候选

1. *When Standard Security Goals Are Not Enough: A State-Aware Formal Analysis of IEEE 802.11 FILS*
2. *PAW-KI: Formalizing Pre-Authentication Work and Key Installation in Wi-Fi Key Establishment*
3. *Standards, Models, and Code: Machine-Checked Analysis of FILS and Its Reference Implementation*

### 1.2 贡献（claim-safe 版本）

1. **首个覆盖 FILS 密钥建立 + 密钥安装语义的机器验证**（不主张“首个 FILS 形式化分析”——Zhang 2018 的 Scyther 模型是 prior art）。
2. **把三类标准未列出的目标写成可判定查询**，并给出反例：PMKID 链接性、未认证 M1/M2 工作可达、PTK 重装。
3. **PAW-KI 双层方法**：预认证工作量（PAW）+ 密钥安装状态（KIS），在 FILS SK/PK 与 WPA2 4-way 上落地。
4. **标准—模型—实现三方对照**：FILS PK 未实现、PTK 重装被实现加固、PMKID 链接性取决于 `(SPA, PMKID)` 查找键。

> 写作注意：贡献 2 的“反例”是**已知攻击的机器化**（Kraken CCS'18、Lee & Chung 2015、PMKID 实践共识）。现有工作**没有新攻击**；新增的是形式化结论、假设敏感性分析和实现证据。

## 2. 威胁模型与范围（可直接改写进论文）

- **密码学**：Dolev-Yao 符号模型；AEAD 用“AAD 不匹配即解密失败”的 reduction；DH 用固定群 + 交换律；哈希/HMAC/KDF 为完美函数。
- **攻击者**：可读、改、删、重放、注入空口帧；可伪造 MAC；可控制 M1 的明文参数；**不**建模：时间、CPU、内存、队列、PHY、计算复杂度、侧信道。
- **角色**：STA、AP（含 ESS 内多 AP 的扩展模型）、后端 rMSK 作为私有不变量。
- **不在范围**：EAP-RP 的密码学、证书链的计算安全性、实现侧信道、MLO（后续工作）。

## 3. 工作线 W1：形式化分析

### 3.1 基线：标准目标全部成立

| 模型 | 查询数 | 结果 | 覆盖 |
|---|---|---|---|
| `FILS_SK.pv` | 22 | 全 true | GTK/TK/PMK/rMSK 保密；ANA=4/5/5C 双向认证 + 单射；PTK 一致性/唯一性；AKM 不跨用 |
| `FILS_PK.pv` | 17 | 全 true | GTK/TK/缓存 PMK 保密；无缓存/缓存两组认证 + 单射；PTK 一致性/唯一性；`CacheUse ⇒ CacheStore` |
| `FILS_PFS.pv` | 3 | PK true / SK5 true / SK4 **false** | PK 与 SK-PFS 有前向保密；SK(ANA=4) 无 PFS（标准允许的设计取舍，作为对照） |

**PFS 这条要写进论文**：它是“标准目标成立”与“标准允许弱化”的边界，不是攻击。`FILS_PFS.pv` 的 phase-1 泄露实验给出确定性结论。

### 3.2 三类扩展目标（核心结果）

#### (a) PMKID 链接性

| 模型 | G-P1 同 PMKID ⇒ 同会话 | G-P2 同 PMKID ⇒ 同 MAC | 机密性 |
|---|---|---|---|
| `FILS_SK_PRIVACY.pv`（PMKID-only 查找） | false | **false** | true |
| `FILS_PK_PRIVACY.pv`（同上，PK 分支） | false | **false** | true |
| `FILS_SK_PRIVACY_MACBOUND.pv`（按 (SPA,PMKID) 查找） | false | **true** | true |
| `FILS_PRIVACY_EQUIV.pv`（观察等价） | — | **cannot be proved** | — |

**写法**：PMKID 的**值**不绑 MAC（`H(EAP-Initiate/Reauth)`），但参考实现的**查找**绑 MAC。因此“MAC 随机化失效”是**实现相关**结论，不是标准层保证。这是本文比“已知隐私问题”更有价值的地方。

#### (b) 未认证 M1/M2 工作

`FILS_DOS_M1M2.pv`（3 个有限槽 + 无限伪造者 + 诚实 STA）：

```text
ApWorkM1(a,s,se,sl) ==> StaStart(s,a,se)        false   ← 未认证工作可达
ApWorkM2(a,s,se,sl) ==> StaStart(s,a,se)        false
SlotBusy(slot1..3, sta_fake) 同时成立            可达    ← 同一伪造身份占满三槽
HonestDone                                     可达    ← 非空验证
ApAuth(a,s,se) ==> ApWorkM2(a,s,se,sl)          true    ← 工作早于认证
```

`FILS_DOS_UNAUTH.pv`（更早的版本）给出同一结论的简化形式：`ApWork ==> StaStart` false。

#### (c) PTK 重装（KRACK）

| 模型 | 分支 | `ApReinstalls` 不可达 | `ApReplaySeen` 可达 | 机密性 |
|---|---|---|---|---|
| `FILS_KRACK_SK_bad.pv` | SK | **false（可达）** | 可达 | true |
| `FILS_KRACK_SK_good.pv` | SK + Session 去重 | **true** | 可达 | true |
| `FILS_KRACK_PTK_bad.pv` | PK | **false（可达）** | 可达 | true |
| `FILS_KRACK_PTK_good.pv` | PK + Session 去重 | **true** | 可达 | true |

**关键句**：重装**不泄露** PTK/GTK（机密性仍 true），危害是“同一 PTK 装两次 → 删建 PTKSA → PN 复位 → nonce 复用”。PN 语义超出 ProVerif，由 Tamarin/ASMETA 补（见文档 03）。

### 3.3 方法：PAW-KI

- **PAW**：`Start / Work / Auth / Slot` 四类事件；查询 `Work ==> Auth`、`Work ==> Start`、`Slot(1..n) 同时成立`。
- **KIS**：`Derive / Install / Use`；查询 `Install` 唯一性（KIS-1）、`Install ⇒ Derive`（KIS-4）。
- **KIS-2/5**（计数器单调、重装后不复用）需要 Tamarin 全局状态。

**第二个协议的落地实例**（证明方法可移植）：

| 模型 | PAW | KIS-1 | 重放分支 | 机密性 |
|---|---|---|---|---|
| `METHOD_4WAY_PAW_KIS_bad.pv` | false | **false（可重装）** | 可达 | true |
| `METHOD_4WAY_PAW_KIS_good.pv` | false | **true** | 可达 | true |

**两个可写结论**：
1. PAW 与 KIS **正交**：修好去重不会让 PAW 变 true，必须分别验证；
2. 建模错误会被基线查询抓住：初版把 GTK 明文放 Msg3，`attacker(gtk)` 立刻 false；改为 `enc((GTK,MIC),KEK)` 后恢复 true。

### 3.5 可以写成“增量”的三条

1. **PFS 边界**：PK 与 SK-PFS 有 PFS，SK(ANA=4) 没有——这是标准明确允许的取舍，模型给出确定性对照。
2. **假设敏感性**：同一隐私目标，在“PMKID-only 查找”和“MAC 绑定查找”下结果相反；这解释了文献与实现之间的分歧。
3. **方法可移植**：同一 PAW/KIS 事件与查询套到 4-way 上仍然有效，且两目标正交。

## 4. 工作线 W2：标准 vs 实现（结论摘要）

> 详细清单与代码定位见 `02_实现核查清单与代码定位.md`。这里只放可直接进论文的结论。

| # | 关键点 | 标准 | 参考实现（wpa_supplicant/hostapd 2.12） | 判定 |
|---|---|---|---|---|
| 1 | FILS PK 支持 | §12.11 定义了 PK 流程 | 4 处 `TODO: FILS PK`（无签名/证书/KeyAuth 处理） | **标准有、实现无** |
| 2 | PTK 重装 | §12.11.2.1 只强制组密钥 | `tk_already_set` + `fils_completed` + 跳过 `sta_remove` | **实现严于标准** |
| 3 | PMKSA 查找键 | PMKSA 含 SPA | `(SPA, PMKID)` 匹配（AP 与 STA 两侧） | **实现绑 MAC，模型未绑** |
| 4 | PMKID 计算 | `Truncate-128(Hash(EAP-Initiate/Reauth))` | `fils_pmkid_erp()` 一致 | 符合 |
| 5 | GTK/IGTK/BIGTK 重装 | §12.11.2.1 强制拒绝 | “Not reinstalling already in-use …” | 符合 |
| 6 | FILS Session 校验 | 相等比较 | `memcmp` 一致 | 符合 |

**这 6 条就是“保障协议安全性的关键点”的第一版**：2、5、6 是实现必须做对的；1 是标准与部署的缺口；3 是决定隐私结论是否成立的开关。

## 6. 可直接使用的文本

### 6.1 中文摘要（草稿）

> FILS（Fast Initial Link Setup，IEEE 802.11ai，现为 802.11-2024 §12.11）把 Wi-Fi 接入压缩为四帧，但其安全目标只覆盖机密性与认证。本文用 ProVerif 对 FILS 的共享密钥（SK）与公钥（PK）两条分支做机器验证：标准目标全部成立（22/17 条查询），但标准未列出的三类目标——PMKID 不可链接、预认证工作不可放大、PTK 只安装一次——全部被反例否定。进一步地，我们把模型与参考实现（wpa_supplicant/hostapd 2.12）对照，发现：FILS PK 在实现中尚未实现；PTK 重装被实现以超出标准的守卫阻止；PMKID 链接性取决于 PMKSA 缓存是否按 MAC 绑定。最后提出 PAW-KI 双层方法，并在 WPA2 4-way 上验证其可移植性。

### 6.2 English abstract（草稿）

> FILS (Fast Initial Link Setup, IEEE 802.11ai, now §12.11 of 802.11-2024) compresses Wi-Fi authentication into four frames, but its stated security goals cover only secrecy and authentication. We present a machine-checked ProVerif analysis of FILS key establishment and key installation for both the shared-key (SK) and public-key (PK) variants. The standard goals hold (22 and 17 queries). We then formalize three goals the standard does not state — PMKID unlinkability, non-amplification of pre-authentication work, and single PTK installation — and show that all three fail. Auditing the reference implementation (wpa_supplicant/hostapd 2.12) shows that FILS PK is not implemented, that PTK reinstallation is prevented by guards that go beyond the standard, and that PMKID linkability depends on whether the PMKSA cache is MAC-bound. We finally propose PAW-KI, a two-layer method for pre-authentication work and key-installation state, and validate it on WPA2's 4-way handshake.

### 6.3 prior art 差异（必须写）

- **Zhang 2018（NTU 博士论文）**：Scyther 模型标题是 FILS，实际是两消息 FKR 重认证抽象，只验证 `Secret`/`Nisynch`；**没有**四帧、KeyAuth、AEAD、PMKID、证书/原始公钥、密钥安装。
- **Kraken CCS'18**：人工发现 FILS KRACK；**没有**形式化模型，且明确把新反制的形式化分析列为 out of scope。
- **Cremers et al. USENIX'20**：WPA2 4-way 的 Tamarin 分析；全文 0 次 “FILS”。
- **Lee & Chung 2015**：FILS DoS 的人工分析；无形式化可达性模型。
- **Singh et al. STM'20**：4-way 攻击建模；不覆盖 FILS。

### 6.4 局限性（必须写）

- 符号模型，不覆盖计算安全性、时间/CPU/内存、侧信道；
- DoS 只证“未认证工作可达 + 有限槽可占满”，**不**证“AP 一定被打垮”；
- KRACK 只证“重装事件可达”，PN 复位是后果，需 Tamarin/ASMETA；
- 隐私结论依赖 PMKSA 查找键（已用两个模型对照说明）；
- FILS PK 无公开实现，PK 结论是**规范级**分析。
