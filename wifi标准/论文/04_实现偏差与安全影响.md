# FILS 实现偏差与安全影响（wpa_supplicant / hostapd 2.12）

- **日期**：2026-11-22
- **对象**：`wpa_supplicant-2.12/`、`hostapd-2.12/`
- **标准**：IEEE 802.11-2024 §12.11（FILS）、§13.4.4（FILS-FT）、§11.3.5.3（关联与 PTKSA）
- **范围**：只列**影响安全性**的偏差；密码学核心（PMK/PMKID/PTK、KeyAuth、AEAD AAD、PMKSA 绑定）已核对为符合，见 §4
- **配套模型**：
  - `proverifcode/FILS_SK_IMPL_BINDING.pv`（Session/RSNE 绑定缺失）
  - `proverifcode/FILS_SK_IMPL_REPLAY.pv`（重放 M3 → AP 断开 STA）
  - 基线：`proverifcode/FILS_SK.pv`（22/22 true）

## 1. D1：重放 M3 → AP 断开 STA（高危）

**代码**

```c
/* hostapd-2.12/src/ap/wpa_auth.c:3711 */
if (sm->tk_already_set) {
    wpa_printf(MSG_DEBUG, "FILS: TK already set to the driver");
    return -1;
}
```

```c
/* hostapd-2.12/src/ap/ieee802_11.c:8690 */
if ((sta->auth_alg == WLAN_AUTH_FILS_SK || ... ) &&
    fils_set_tk(sta->wpa_sm) < 0) {
    wpa_printf(MSG_DEBUG, "FILS: TK configuration failed");
    ap_sta_disconnect(hapd, sta, sta->addr, WLAN_REASON_UNSPECIFIED);
    return;
}
```

**触发**：抓一条合法 `(Re)Association Request` 原样重放。AP 的 AEAD/KeyAuth/Session 全部通过（同一 PTK），进入 `handle_assoc_cb`；`tk_already_set` 已为 true → 返回 -1 → **断开合法 STA**。

**标准要求**：重复关联应按重传处理（重发缓存响应或忽略），不应把“已安装同一 PTK”当作致命错误；§11.3.5.3(m) 也只规定成功关联时删除旧 PTKSA，没有要求断开。

**威胁模型**：仅需嗅探 + 重放，不需要 MitM；非 PMF 部署（公共热点/OpenRoaming）无 SA Query 兜底。

**ProVerif 验证**（`FILS_SK_IMPL_REPLAY.pv`）

- bad 对（无去重）：`ApDeauth` 可达 → 查询 `event(ApDeauth(a,s))` 为 **false**
- good 对（去重）：`ApDeauth(ag,sg)` 为 **true**（不可达）
- 非空性：`ApReplaySeen` 在两对均可达（false）
- 机密性：`attacker(probe)` 为 true（攻击是可用性，不是密钥泄露）

**修复**：`fils_set_tk` 区分“重复安装”与“失败”；`handle_assoc_cb` 对重复只重发缓存 M4，不 `ap_sta_disconnect`。

> **下游变体（O1，仅 OpenWrt）**：OpenWrt 的 `021-fix-sta-add-after-previous-connection.patch` 在 `add_associated_sta()` 中增加了 `(!reassoc && AUTHORIZED)` 子句，使重放的 Association Request 先删除 STA 并触发 `WPA_DRV_STA_REMOVED`（清 `tk_already_set`），随后 `fils_set_tk()` 会用同一 PTK 重新下装，把本节的“断开”变成“静默 TK 重装/PN 复位”。详见 `05_Android_OpenWrt_实现偏差.md` 的 3.1 节。

## 2. D2/D4：STA 的 Session/RSNE 校验缺失（中-高）

### D2：Session 不一致只打印

```c
/* wpa_supplicant-2.12/src/rsn_supp/wpa.c:6958 */
if (os_memcmp(elems.fils_session, sm->fils_session, FILS_SESSION_LEN) != 0) {
    wpa_printf(MSG_DEBUG, "FILS: FILS Session mismatch");
    wpa_hexdump(...);
    wpa_hexdump(...);
    /* 没有 goto fail */
}
```

对比同文件处理 Auth Response 的同类检查（`wpa.c:6462`）是 `goto fail` 的。

### D4：缺 RSNE 继续接受

```c
/* wpa_supplicant-2.12/src/rsn_supp/wpa.c:6967 */
if (!elems.rsn_ie) {
    wpa_printf(MSG_DEBUG, "FILS: No RSNE in (Re)Association Response");
    /* As an interop workaround, allow this for now ... */
} else if (wpa_compare_rsn_ie(...)) {
    goto fail;
}
```

代码注释自认“严格解释标准应 `goto fail`”。

**标准**：§12.11.2.6.3 要求 Session 不一致即失败，并校验 RSNE 的 AKM/cipher/RSN Caps 与 AP 通告一致。

**威胁模型与边界**：

- 在 **mac80211** 栈中，关联帧的 AES-SIV AAD 由内核 `net/mac80211/fils_aead.c` 校验，AAD 含 Session；因此仅“supplicant 漏检”不直接可利用。
- 对 **FullMAC/厂商驱动**，若驱动不校验 AAD（或把已解密帧交给 supplicant），D2 就是最后一道检查，缺失即会话错绑；D4 则直接跳过配置一致性。

**ProVerif 验证**（`FILS_SK_IMPL_BINDING.pv`）

同文件放置两对：

- 标准对（s1/a1）：校验 Session/RSNE，且两者进入 AAD；
- 偏差对（s2/a2）：不校验，且 AAD 不含两者（代表“驱动不校验 AAD”的最坏情况）。

攻击者改写 AP 的 Assoc Response 的 Session/RSNE；偏差对接受，事件记录“实际收到的值”。

| 查询 | 结果 |
|---|---|
| `StaFinStd ==> ApFinStd`（标准对） | **true** |
| `StaFinDev ==> ApFinDev`（偏差对） | **false（反例）** |
| `StaFinStd` / `StaFinDev` 可达性 | false（均可达，非空验证） |
| `attacker(probe)` | true（密钥仍保密） |

**修复**：两处都改为 `goto fail`；RSNE 缺失按标准拒绝（或明确配置开关并默认拒绝）。

## 3. D3：AP 未做 Auth↔Assoc 的 RSNE 一致性比较（中）

**代码**

- Auth：`handle_auth_fils` 调 `wpa_validate_wpa_ie()`（`hostapd-2.12/src/ap/ieee802_11.c:3008`）
- Assoc：`check_assoc_ies` 再调一次（同文件 `5737`）
- `wpa_validate_wpa_ie()` 末尾直接覆盖：

```c
/* hostapd-2.12/src/ap/wpa_auth_ie.c:1465 */
if (sm->wpa_ie == NULL || sm->wpa_ie_len < wpa_ie_len) {
    os_free(sm->wpa_ie);
    sm->wpa_ie = os_malloc(wpa_ie_len);
}
os_memcpy(sm->wpa_ie, wpa_ie, wpa_ie_len);
sm->wpa_ie_len = wpa_ie_len;
```

没有与 Auth 帧的 RSNE 比较。

**标准**：§12.11.2.6.2 要求 Assoc RSNE 的 AKM/cipher/RSN Caps 与 Auth RSNE **完全一致**。

**影响**：M3 受 AEAD 保护，远程攻击者改不了；但**恶意 STA** 可以在策略允许的算法间切换，使 `sm->pairwise`/`wpa_key_mgmt` 与派生 PTK 所用参数不一致（`fils_set_tk` 用更新后的 `sm->pairwise` 选算法）。

**状态**：代码级证据充分；ProVerif 需要“恶意 STA + 策略一致性目标”，不在本次两个模型的范围内（见 §5 的未覆盖项）。

## 4. D5–D9 简述

### D5 状态码（中）
- 无 PMK：`prepare_auth_resp_fils` 返回 **1**（`ieee802_11.c:3300-3305`），标准要求 **53**（§12.11.2.3.3 d)2）。
- ERP 失败：返回 **1**（`ieee802_11.c:3373`），标准要求 **15**。
- 未知 AS：未实现 **113**（§12.11.2.3.4），依赖 RADIUS 结果。
- 影响：客户端回退/重试行为不标准；对“PMKID 预言机”反而更不可区分（碰巧更隐私，但不合规）。

### D6 FILS-FT MDE/FTE（中）
- `wpa.c:6411` `/* TODO: Check MDE and FTE payload */`。
- 仅检查 R0KH-ID/R1KH-ID 存在并拷贝；未校验 MDE 与 Beacon/自身一致、FTE 字段合法性。
- 部分由后续 PMKR1Name 比较（`wpa.c:7056-7069`）兜底，但不满足 §13.4.4 的完整校验。

### D7 RSNXE（低-中）
- `wpa.c:6987-7008`：若 STA 未在 Assoc Req 带 RSNXE，则允许 Response 中 RSNXE 不匹配。
- 影响 secure LTF/MLO 等能力位的一致性。

### D8 Session 长度（低）
- `hostapd-2.12/src/ap/wpa_auth.c:3350`：`ie[1] >= 1 + FILS_SESSION_LEN` 即接受，取前 8 字节。
- 标准要求 8 字节（§9.4.2.178）；多出的字节进入 AAD，无直接密钥影响。

### D9 未认证 M1 的 DoS（中，可用性）
- `hostapd-2.12/src/ap/ieee802_11.c:2907-2969`：格式合法即做 ECDH、分配 `fils_ecdh/g_sta/dh_ss`。
- 无 anti-clogging、无 ERP pending 上限/限速；标准未要求，属标准缺口 + 实现未加固。
- ProVerif 无 CPU/状态/时间语义，不能直接证明“打垮”；只能证明“未认证工作可达”（已有 `FILS_DOS_UNAUTH.pv`）。

## 7. 未覆盖 / 边界

- **D3（AP RSNE 一致性）**：需要“恶意 STA + 策略一致性”目标；本次未建模，代码证据已足够。
- **D5（状态码）**：属客户端行为/互操作，不是机密性/认证性目标；需要可用性/状态机模型。
- **D6（FILS-FT）**：需要 FT 密钥层级（PMK-R0/R1、FTE MIC），不在 FILS_SK 模型范围。
- **D7/D8**：低影响解析宽松，未单独建模。
- **D9（DoS）**：ProVerif 无时间/CPU/队列语义；只能证“未认证工作可达”，不能证“打垮”。
- **D2/D4 的可利用性依赖驱动**：mac80211 的 `fils_aead.c` 会校验 AAD；FullMAC/厂商驱动不保证。模型中的偏差对同时移除了 AAD 绑定，代表最坏情况。

## 9. 论文中的写法（claim-safe）

> 参考实现（wpa_supplicant/hostapd 2.12）的 FILS 密码学核心与 §12.11 一致，但在状态机与校验细节上有 6 处影响安全性的偏差：其中“重放 M3 导致 AP 断开 STA”可用一条抓包触发（可用性），而“STA 漏检 Session/RSNE”在 `AAD` 未被驱动校验时导致会话/配置错绑。我们用两个 ProVerif 变体把这两类缺口落到可判定查询上：标准模型的目标为 true，注入实现缺失后目标变为 false（反例可达），且密钥保密性仍为 true——说明这些缺口的危害是绑定与可用性，而非直接密钥恢复。
