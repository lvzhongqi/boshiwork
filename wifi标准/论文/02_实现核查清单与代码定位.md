# FILS 实现核查清单与代码定位

- **日期**：2026-11-21
- **用途**：把“保障 FILS 安全性的关键点”拆成可核查条目，给出**标准依据、期望行为、失败后果、代码位置、grep 关键字、判定标准**
- **对照实现**：`wpa_supplicant-2.12`（本地，含 hostapd 共享的 `src/ap`）；hostapd 主程序需另外下载
- **状态图例**：✅ 已核查并得出结论　⬜ 待核查　⚠️ 缺源码/需完整树

> 行号来自本地 `wpa_supplicant-2.12` 树，换版本会偏移；引用时统一写 `文件:函数`，行号只作定位辅助。

---

## 0. 使用方法

1. 每条按 **ID → 关键点 → 标准 → 期望 → 违反后果 → 代码位置 → 判定** 核查；
2. 结论写入第 6 节的记录模板，格式固定为 `文件:行号 + 代码摘录 + 判定`；
3. 无法从代码判断的，标 ⚠️ 并转入动态验证（第 5 节）；
4. 优先做 A、D、E 三组：它们直接对应论文的三类结论（PK 缺口、KRACK、隐私）。

## 4. 已核查结论（可直接写进论文）

| # | 结论 | 证据 | 与模型的关系 |
|---|---|---|---|
| 1 | FILS PK 未实现 | 4× `TODO: FILS PK`（`ieee802_11.c:2905/3191`，`wpa.c:6216/6311`）；`defs.h` 无 `*_PK` AKM | PK 模型是规范级分析 |
| 2 | PTK 重装被实现阻止 | `fils_set_tk` 的 `tk_already_set` 守卫；`fils_completed`；跳过 `sta_remove` | `_good` 对应实现，`_bad` 对应无加固实现 |

| 5 | 组密钥拒绝重装 | “Not reinstalling already in-use …” | 与 `FILS_GTK_REPLAY_good.pv` 一致 |
| 6 | FILS 默认不编译 | `wpa_supplicant/defconfig:609,611` 注释 | 部署讨论要提“编译开关” |

## 5. 动态验证方案（可选，但很有说服力）

**拓扑**：一台 Linux（VM 亦可）

```text
mac80211_hwsim (2 个 radio)
  radio0 = AP    : hostapd + CONFIG_FILS
  radio1 = STA   : wpa_supplicant 2.12 + CONFIG_FILS
  第三个 monitor 接口用于抓包/注入
```

**实验 1：重放 M3（KRACK）**

1. 正常完成一次 FILS SK（`wpa_supplicant -dd` 打开调试）；
2. 用 `scapy`/`tcpreplay` 重放记录到的 `(Re)Association Request`；
3. 观察日志中是否再次出现 `FILS: Configure TK to the driver`；
4. 判定：没有再出现 ⇒ `_good` 得到实现验证；出现 ⇒ 真实漏洞（升级论文）。

**实验 2：PMKID 存在性预言机**

1. 记录一次正常接入的 PMKID；
2. 用伪造源 MAC 的 M1（RSNE 带该 PMKID）发往 AP；
3. 观察回包：M2（含 ANonce）还是 Status 53；
4. 判定：可区分 ⇒ 预言机成立；不可区分 ⇒ 否证（并检查是否所有失败都超时）。

**实验 3：未认证 M1 占槽**

1. 配置 `max_num_sta=8`；
2. 循环发送不完成 M3 的 M1（不同 MAC 或同一 MAC）；
3. 测“占满时间”“诚实 STA 接入失败率”；
4. 判定：能占满且无速率限制 ⇒ 定量 DoS；有限速 ⇒ 记录缓解参数。

**实验 4：PMKID 与 MAC 随机化**

1. 正常接入一次，记录 PMKID；
2. 修改 `wpa_supplicant` 的 `own_addr`（或换虚拟 STA MAC）再接入；
3. 观察 M1 是否仍带同一 PMKID；
4. 判定：仍带 ⇒ 该实现存在跨 MAC 链接；不带 ⇒ 支持“实现相关”结论。
