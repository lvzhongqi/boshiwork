01 · Related Work 研究现状

三条研究线已成熟，但移动端仍缺一面“总账”

LLM、GUI 与系统安全各自都有积累，但既往工作多聚焦 Web Agent 或单点漏洞，尚未覆盖移动 Agent 的完整执行链。

L
Model layer

LLM 层：输出可被操纵

  • 提示注入、越狱与后门攻击
  • Glitch Tokens 触发异常推理
  • 模型对“看似合法”的恶意输入缺乏稳定防御
G
GUI layer

GUI 层：感知可被欺骗

  • UI deception、透明浮层与点击劫持
  • ViewTree / 层级注入污染结构理解
  • 视觉与结构两套感知路径各有盲区
S
System layer

System 层：能力可被滥用

  • Intent / Deeplink 劫持与包名伪造
  • 日志未脱敏导致上下文泄漏
  • 高权限执行放大单点漏洞的影响
Gap · 既有工作的空白

Web/GUI Agent 研究较多，但移动环境独有的系统权限、UI 结构、多模态输入没有被放进同一威胁模型；缺少可复用的端到端评测方法。

This paper · 本文定位

论文主张这是首个覆盖三类移动 LLM Agent 的系统性安全分析：统一工作流 → 11 个攻击面 → AgentScan 半自动评测。

KEY SHIFT 不是把三个领域简单拼起来：移动 Agent 的独特性在于三层能力被同一个执行闭环串起来，单层防御无法覆盖跨层组合攻击。

模型层
02

模型层攻击

指令理解与推理决策

攻击对象是模型对指令与上下文的理解。攻击者把恶意目标包装成正常任务，或用异常字符扰乱推理，让模型在“看似合理”的判断中改写计划、跳过校验，把错误决策交给执行层。

输入污染恶意任务或异常字符进入模型上下文
推理偏移原始目标被覆盖，计划与约束失效
动作越权错误决策被直接执行到真实设备
为什么有效Agent 被设计为忠实执行、少人工确认；模型输出又直接驱动真实操作，一次判断偏差就会被放大成设备上的动作。
作用点指令理解 · 任务分解 · 决策生成
界面层 · 覆盖最广
06

界面层攻击

屏幕感知与点击决策

攻击对象是屏幕感知与点击决策。攻击者伪造控件、图标或界面文本，污染 ViewTree 或遮挡层级，让 Agent 看到的界面与真实状态不一致，从而点错目标、走错页面。

界面伪造假控件、仿冒图标与恶意屏幕文本
感知污染OCR 定位偏移，控件树结构被篡改
交互劫持点击被重定向，或任务直接中断
为什么有效截图、OCR、控件树与坐标点击都可能被注入；感知层缺少可信基准，越依赖视觉就越容易被误导。
作用点屏幕理解 · 控件定位 · 点击执行
系统层
03

系统层攻击

系统调用与接口滥用

攻击对象是系统调用接口。攻击者注册同名包、构造恶意 Deeplink，或读取运行时日志，把 Agent 的启动、跳转与上下文暴露变成可利用的入口。

接口伪造同名包、恶意 URI 或可读取的日志
目标重定向启动恶意组件或进入钓鱼页面
数据外泄查询参数、屏幕状态与指令被带走
为什么有效系统接口默认信任调用方；包名、URI 与日志缺少校验或脱敏，单点缺口就能放大为应用劫持与隐私泄漏。
作用点应用启动 · 页面跳转 · 运行日志

从指令到视觉：让 Agent 说错、看错

01模型层

恶意指令

把恶意目标包装成正常任务

把恶意目标包装成正常子任务，利用模型对指令的服从覆盖原始目标；缺少校验时，Agent 会直接执行越权操作，甚至把攻击步骤当成任务的一部分。

攻击链
1
恶意包装把攻击目标写成子任务
2
模型顺从覆盖原始意图与边界
3
越权执行发消息、删文件、取数据
后果发送消息 · 删除文件 · 读取敏感数据
02模型层

异常字符注入

用异常字符破坏推理稳定性

在输入中注入异常字符或对抗后缀，使模型输出漂移、遗忘目标或执行非预期动作；这类输入还可绕过关键词过滤，常作为复合攻击的触发器。

攻击链
1
异常注入插入异常字符或对抗后缀
2
推理漂移输出偏离原始目标
3
行为异常执行非预期动作
后果任务偏离 · 输出失控 · 绕过过滤
03GUI 层

界面元素伪造

伪造按钮与输入框，诱导错误点击

伪造与真实控件视觉一致的按钮、输入框或图标，利用 OCR 与视觉定位的盲区，让 Agent 把伪造元素当成真实控件并点击。

攻击链
1
伪造控件复制真实按钮与输入框
2
视觉误判OCR 与定位被欺骗
3
错误点击触发攻击者控件
后果误触 · 误输入 · 跳转钓鱼页
04GUI 层

应用仿冒

同名同图标，诱导启动恶意克隆

安装与合法 App 同名、同图标的恶意克隆，利用 Agent 对图标与名称的视觉信任，诱导其打开仿冒应用，并由恶意组件接管后续交互。

攻击链
1
仿冒应用同名同图标的恶意克隆
2
视觉信任Agent 按图标与名称启动
3
接管交互恶意组件接收后续操作
后果应用劫持 · 凭据窃取 · 数据外传

结构污染与交互劫持：让 Agent 找不到、点错

05GUI 层

视图树干扰

污染界面层级，让 Agent 误判结构

通过浮层或悬浮组件污染视图树的层级与控件属性，使 Agent 找不到关键控件、误判界面状态，进入无限重试或直接终止任务。

攻击链
1
污染层级注入浮层与伪造属性
2
结构误判找不到关键控件
3

后果任务中断 · 无限重试 · 错误决策
06GUI 层

屏幕文本注入

把恶意提示混入可见文本

把“取消任务”“立即安装”等提示写进屏幕文本；LLM 会把所有可见文本当作上下文，从而改写决策、引导 Agent 执行攻击者指定的动作。

攻击链
1
写入文本屏幕出现恶意提示
2
上下文污染LLM 把文本当指令
3
决策改写取消任务或安装应用
后果任务取消 · 应用安装 · 决策被改写
07GUI 层

透明浮层

用不可见窗口劫持点击

用不可见浮层覆盖真实按钮，触摸事件被拦截并重定向到攻击者控制的界面；视觉上几乎无法察觉，常能绕过常规的界面检测。

攻击链
1
覆盖浮层透明窗口盖住真按钮
2
拦截触摸事件被重定向
3
劫持点击进入攻击者界面
后果点击劫持 · 转账重定向 · 操作失控
08GUI 层

弹窗干扰

在决策与执行之间插入窗口

在点击决策完成、动作执行之前弹出窗口，遮挡或抢占交互；依赖坐标点击的 Agent 往往不会重新校验屏幕状态，点击会被导向弹窗内容。

攻击链
1
决策完成Agent 已选定目标
2
插入弹窗执行前抢占界面
3
交互偏移点击被导向弹窗
后果交互抢占 · 任务偏离 · 恶意流程触发

系统层
01

包名伪造

同名包与图标仿冒

注册与合法 App 相同的包名与图标，利用 Agent 只按包名启动、缺少签名与身份校验的缺陷，让恶意克隆接管后续交互。

1注册同名包复制合法 App 的包名、图标与名称
2诱导启动Agent 按包名或视觉线索选择应用
3接管操作恶意克隆接收并记录后续交互

应用劫持凭据窃取
为什么有效系统 Intent 只按包名寻址，缺少签名与来源校验，Agent 无法区分同名应用。
影响仿冒应用可长期驻留，持续窃取操作与凭据。

系统层
02

深度链接伪造

劫持跳转与查询参数

拦截或覆盖 Agent 使用的 URI 跳转，把导航重定向到恶意页面；查询参数还可能携带位置、账号等隐私数据。

1构造 URI伪造指向攻击者页面的深度链接
2覆盖跳转拦截或替换合法导航链路
3重定向页面跳转，查询参数被一并带走
前置条件目标使用可被覆盖的 URI 跳转，且未校验最终页面。
钓鱼跳转参数泄漏
为什么有效URI 跳转默认信任调用方，Agent 不校验最终落地页与参数归属。
影响Agent 被引向钓鱼页面，敏感参数随 URL 一并泄漏。

03

日志泄漏

从运行日志重建上下文

Agent 把屏幕状态、点击坐标与用户指令写入系统日志；其他应用读取后即可还原任务、界面与敏感信息。

1读取日志其他应用访问 Android 系统日志
2重建上下文还原屏幕状态、点击坐标与指令
3提取数据定位账号、位置或银行卡等信息

影响攻击者无需接触设备，即可还原任务与界面状态。

What is measured · 测什么

单 Agent 对已知攻击的鲁棒性；真实设备上的行为偏移、任务完成度与数据暴露；同一任务重复 10 次的稳定成功率。

What is not measured · 不测什么

多 Agent 协同、真实用户行为、端侧模型差异、长期演化与自适应攻击；结论应理解为受控条件下的下界。

03 · Case Study 案例研究

端到端复合攻击：三步拿走银行密码

单点漏洞不是终点，组合起来才是“杀伤链”

论文以 Mobile-Agent-v2 为靶标，在受控实验中把三个层的漏洞串成一次完整攻击。

01 Transparent Overlay · 劫持转账确认 透明浮层覆盖银行 App 的转账确认按钮，Agent 的点击被重定向到攻击者控制的 Activity。
02 Malicious Instruction · 伪装“继续任务” 恶意指令把劫持后的页面包装成任务流程的一部分，诱导 Agent 继续执行而不是中止。
03 Prompt Injection via Display · 读取记忆 屏幕上的伪造提示触发模型回忆敏感信息；Agent 从记忆中取出银行卡密码并填入恶意输入框。
结果：受控实验截图中密码被回填（202504），页面显示 “pwned”。这说明 GUI 劫持 + 指令操纵 + 上下文泄漏可以形成端到端利用。

04 · Defense 防御与缓解

打了补丁，风险显著下降，但没有归零

作者对 Mobile-Agent-v2 做了三项初步加固。结果说明“执行前校验”有效，但单点补丁无法覆盖所有攻击面。

01
动作 ↔ 控件 ↔ 屏幕元素强关联点击前确认目标控件真实存在、可见且与当前动作语义一致。
02
指令 ↔ 屏幕文本严格对齐降低模型把屏幕中的恶意文本误读为用户意图的概率。
03
执行前屏幕校验在关键动作前重新读取 UI 状态，拒绝“决策后被替换”的界面。
最小权限 多模态交叉验证 敏感操作二次确认 日志脱敏
仍然存在的风险：Prompt Injection、Glitch Token 与 UI Forgery 只是被削弱，并未被消除；单 Agent 补丁不能替代架构级安全设计。

05 · Conclusion 结论与讨论

当 Agent 获得“看屏幕、点屏幕、调系统”的能力，安全边界必须从模型输出扩展到整条执行链。

01
新能力栈 = 新攻击面LLM × GUI × System 三层耦合，形成 11 个可落地攻击面；不能只用“提示注入”来理解 Agent 安全。
02
风险不是理论上的9 款真实 Agent 全部中招，平均暴露 6.3 / 11；GUI 操纵在多个 Agent 上稳定复现。
03
评测与防御要一起设计AgentScan 提供了可复用的评测骨架；执行前校验能降低风险，但需要权限、感知、意图与日志的协同防护。
